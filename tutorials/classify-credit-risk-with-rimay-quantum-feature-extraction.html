Clasifica el riesgo crediticio con la extracción cuántica de características Rimay de Kipu Quantum

nota

Las Qiskit Functions son una característica experimental disponible solo para los usuarios del Plan Premium, el Plan Flex y el Plan On-Prem (a través de la API de IBM Quantum Platform) de IBM Quantum®. Están en estado de versión preliminar y sujetas a cambios.

Estimación de uso: 2 minutos en un procesador Nighthawk r2. (NOTA: Esto es solo una estimación. Tu tiempo de ejecución puede variar.)

Resultados de aprendizaje​

  • Preparar datos tabulares con columnas categóricas y numéricas para la Qiskit Function Rimay.

  • Ajustar un mapeo de características cuántico con los datos de entrenamiento y mapear los datos de prueba en la misma ejecución.

  • Entrenar modelos clásicos con características transformadas cuánticamente, solas y combinadas con las características originales.

  • Comparar los resultados con una línea base puramente clásica.

Requisitos previos​

Antes de comenzar este tutorial, debes estar familiarizado con los siguientes temas:

  • Introducción a Qiskit Functions

  • Clasificación supervisada con scikit-learn

Contexto​

Muchos problemas de aprendizaje automático en la industria involucran conjuntos de datos tabulares pequeños o medianos, donde agregar más datos no es una opción y la precisión del modelo se estanca. La puntuación del riesgo crediticio es un ejemplo típico. Un prestamista usa unas pocas docenas de atributos para decidir si es probable que el solicitante devuelva el crédito.

Rimay, una Qiskit Function de Kipu Quantum, añade un paso de preprocesamiento cuántico a un flujo de trabajo de este tipo. Implementa el algoritmo de extracción cuántica de características contradiabática digitalizada [1]. Cada característica de entrada se asigna a un qubit. Los valores de las características y la información mutua entre ellas determinan los campos locales y los acoplamientos de un hamiltoniano de vidrio de espín. A continuación, la dinámica contradiabática hace evolucionar el sistema cuántico hacia sus estados de baja energía, y los valores esperados de uno y dos cuerpos medidos al final se convierten en las nuevas características transformadas cuánticamente. Estas características capturan correlaciones no lineales entre las entradas, y puedes alimentar con ellas cualquier modelo clásico.

Este tutorial usa el conjunto de datos German credit de OpenML [2], con 1000 solicitantes y 20 atributos, para entrenar un clasificador de bosque aleatorio. Primero estableces una línea base clásica, luego envías los datos a Rimay y, por último, entrenas el mismo tipo de modelo con las características transformadas cuánticamente, solas y combinadas con las características originales.

Requisitos​

Antes de comenzar este tutorial, asegúrate de tener instalados los siguientes paquetes:

  • Cliente de IBM Quantum Compute (pip install qiskit-ibm-runtime)

  • Qiskit Functions (pip install qiskit-ibm-catalog)

  • scikit-learn (pip install scikit-learn)

  • pandas (pip install pandas)

  • Matplotlib (pip install matplotlib)

También necesitas acceso a la función Rimay del catálogo de Qiskit Functions.

import matplotlib.pyplot as plt
import numpy as np
import pandas as pd
from qiskit_ibm_catalog import QiskitFunctionsCatalog
from sklearn.datasets import fetch_openml
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import (
    accuracy_score,
    f1_score,
    precision_score,
    recall_score,
    roc_auc_score,
)
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import OneHotEncoder

def train_random_forest(x, y, n_estimators, max_depth):
    """Train a random forest classifier with fixed hyperparameters."""
    model = RandomForestClassifier(
        n_estimators=n_estimators,
        max_depth=max_depth,
        min_samples_split=5,
        min_samples_leaf=1,
        max_features="sqrt",
        random_state=42,
        n_jobs=-1,
    )
    return model.fit(x, y)

def evaluate(model, x, y):
    """Return the classification metrics of a trained model on a test set."""
    y_pred = model.predict(x)
    y_proba = model.predict_proba(x)[:, 1]
    return {
        "Accuracy": accuracy_score(y, y_pred),
        "AUC": roc_auc_score(y, y_proba),
        "F1 score": f1_score(y, y_pred),
        "Precision": precision_score(y, y_pred),
        "Recall": recall_score(y, y_pred),
    }

Paso 2: Optimizar el problema para la ejecución en hardware cuántico​

Rimay construye y transpila los circuitos para el procesador que seleccionas, por lo que no hay ningún circuito que optimizar a mano. Especifica el número de shots por circuito, dentro de las siguientes restricciones:

  • Cada característica necesita un qubit, por lo que el procesador debe tener al menos tantos qubits como características tiene el conjunto de datos.

  • Rimay ejecuta un circuito por fila, con las filas de entrenamiento y de prueba juntas. Un solo trabajo puede solicitar como máximo 10 millones de ejecuciones, por lo que el número de filas multiplicado por shots debe mantenerse dentro de ese presupuesto.

Comprueba ambos límites antes de enviar el trabajo.

nota

Un trabajo también debe terminar en un plazo de 24 horas, incluido el tiempo que sus circuitos esperan en la cola; de lo contrario, se detiene sin devolver un resultado.

shots = 5000

n_features = x_train.shape[1]

Calcula el tamaño de la función​

Cada trabajo se ejecuta con un tamaño de función, S, M o L, que selecciona los recursos de cómputo en los que se ejecuta. En el caso de Rimay, el tamaño depende del número de filas que asigna un trabajo, con las filas de entrenamiento y de prueba juntas. Si solicitas un tamaño demasiado pequeño, el trabajo falla con el error 4600. Para conocer los tamaños y sus límites, consulta Function sizes en la guía de Rimay.

La siguiente celda define el calculador de tamaño. Se ejecuta en tu máquina, lee solo los datos que le pasas y no envía nada.

from os import PathLike
from typing import Any, Literal, Sequence, Sized

Size = Literal["S", "M", "L"]

# Upper bounds (inclusive) in samples.
_SMALL = 2_999
_MEDIUM = 9_999

FIT_TRANSFORM, TRANSFORM, DELETE = "fit-transform", "transform", "delete"

# Which positions of input_file hold samples, per mode. The labels in
# y_train submit no circuits of their own, so they are not counted.
SAMPLE_POSITIONS = {FIT_TRANSFORM: (0, 2), TRANSFORM: (0,)}

def calculate_function_size(problem: Sequence[Sized], **kwargs: Any) -> Size:
    """Return the size ("S", "M" or "L") required to run the function."""
    metrics = _measure(problem, **kwargs)
    if _is_small(metrics):
        return "S"
    if _is_medium(metrics):
        return "M"
    return "L"

def _measure(problem: Sequence[Sized], **kwargs: Any) -> dict:
    """The samples the job submits."""
    return {"samples": count_samples(problem, kwargs.get("mode"))}

def count_samples(problem: Sequence[Sized], mode: Any) -> int:
    """Rows across the data sets of ``problem`` that carry samples."""
    if mode == DELETE:
        return 0
    if mode not in SAMPLE_POSITIONS:
        raise ValueError(f"cannot size mode {mode!r}")
    if _is_name(problem) or (
        isinstance(problem, (list, tuple))
        and any(_is_name(data) for data in problem)
    ):
        raise TypeError(
            "pass the data, not the file name: read each input_file, e.g. with "
            "pandas.read_csv, and pass the data sets in input_file order"
        )
    if not isinstance(problem, (list, tuple)):
        raise TypeError(
            "pass a list of data sets in input_file order, e.g. [x_train, y_train], "
            f"not a single {type(problem).__name__}"
        )
    return sum(
        len(problem[i]) for i in SAMPLE_POSITIONS[mode] if i < len(problem)
    )

def _is_name(value: Any) -> bool:
    """A file name or path rather than data."""
    return isinstance(value, (str, bytes, PathLike))

def _is_small(metrics: dict) -> bool:
    """Determine if the metrics fit T-size 'S'."""
    return metrics["samples"] <= _SMALL

def _is_medium(metrics: dict) -> bool:
    """Determine if the metrics fit T-size 'M'."""
    return metrics["samples"] <= _MEDIUM

Pasa los conjuntos de datos en el mismo orden que los archivos de input_file, junto con el modo de la ejecución:

size = calculate_function_size(
    [x_train, y_train, x_test], mode="fit-transform"
)
print(size)

Paso 3: Ejecutar con las primitivas de Qiskit​

Ejecuta Rimay en modo fit-transform. Ajusta una asignación cuántica de características con x_train.csv y y_train.csv, y asigna con ella tanto el conjunto de entrenamiento como el de prueba. El orden de los archivos en input_file importa. Indica primero las características de entrenamiento, luego las etiquetas de entrenamiento y, por último, las características de prueba opcionales. Pasa el tamaño que calculaste como function_size.

job = rimay.run(
    mode="fit-transform",
    input_file=[
        "x_train.csv",
        "y_train.csv",
        "x_test.csv",
    ],  # This order matters
    backend_name=backend.name,
    shots=shots,
    function_size=size,
)

El resultado contiene un mapping_id, que identifica la asignación que ajustó esta ejecución. No lo necesitas en este tutorial, porque el conjunto de prueba se asignó en la misma ejecución. Guarda este ID si quieres asignar filas nuevas más adelante con mode="transform". Es la única forma de acceder a la asignación ajustada y, sin él, debes ajustar y pagar una nueva. La asignación se construye para la disposición de qubits de este procesador, por lo que una ejecución transform posterior debe pasar el mismo backend_name.

Entrena con las características clásicas y cuánticas combinadas​

Apila las características originales y las transformadas cuánticamente, y entrena el mismo modelo con la combinación.

El AUC mide qué tan bien un modelo ordena los créditos buenos por encima de los malos, independientemente de un umbral de decisión, lo que lo convierte en la métrica más informativa en este conjunto de datos desbalanceado (70 % de créditos buenos). En los benchmarks de Kipu Quantum, las características transformadas cuánticamente por sí solas alcanzaron un AUC similar al de la línea base clásica, y el modelo híbrido, que combina ambas, alcanzó el AUC y la puntuación F1 más altos. Por lo tanto, las características transformadas cuánticamente aportan información que las características clásicas no proporcionan por sí solas.

Limpieza (opcional)​

Una asignación ajustada permanece disponible hasta que la elimines. Si no quieres asignar más datos con ella, elimínala. Una eliminación no realiza trabajo cuántico, no usa tiempo de QPU y no se puede deshacer.

Conclusión​

Lo que lograste​

En este tutorial, lograste lo siguiente:

  1. Preparaste un conjunto de datos reales de riesgo crediticio con atributos categóricos y numéricos para la extracción cuántica de características.

  2. Estableciste una línea base de bosque aleatorio clásico.

  3. Usaste Rimay para ajustar una asignación cuántica de características en hardware cuántico y asignar los conjuntos de entrenamiento y de prueba en una sola ejecución.

  4. Entrenaste el mismo modelo con características transformadas cuánticamente y con características combinadas, y las comparaste con la línea base.

Puntos clave​

  • Rimay encaja en un flujo de aprendizaje automático existente como un paso adicional de preprocesamiento. Conservas tu preparación de datos y tu modelo clásico.

  • El número de qubits limita el número de características de entrada, y el número de filas multiplicado por shots limita el tamaño de un solo trabajo.

  • Usa por defecto las características transformadas cuánticamente combinadas con las características originales, porque el modelo puede aprovechar ambas.
