Preguntas frecuentes (FAQ)

Para preguntas frecuentes específicas sobre los modos de ejecución, consulta la guía FAQ sobre modos de ejecución de Qiskit Runtime.

¿Cómo cito Qiskit en mi investigación?​

Cita Qiskit utilizando el archivo BibTeX incluido.

¿Cómo cito un computador IBM Quantum en mi investigación?​

Para artículos de investigación, animamos a los autores a reconocer IBM Quantum® usando:

Reconocemos el uso de los servicios de IBM Quantum para este trabajo. Las opiniones expresadas son las de los autores y no reflejan la política oficial ni la posición de IBM o del equipo de IBM Quantum.

Las referencias bibliográficas del artículo deben usar la siguiente cita:

IBM Quantum. https://quantum.cloud.ibm.com/, YYYY

Las unidades de procesamiento cuántico en el artículo deben referenciarse por su nombre único (por ejemplo, ibmq_vigo) y, opcionalmente, añadir la versión (por ejemplo, ibmq_vigo v1.0.2). También recomendamos hacer referencia al procesador. Por ejemplo:

En este artículo utilizamos ibmq_vigo, que es uno de los procesadores IBM Quantum Canary.

Ejemplo de cita de un programa de IBM Quantum:

IBM Quantum (2025). Estimator primitive (Version x.y.z) [computer software]. https://quantum.cloud.ibm.com/

¿Cómo cito IBM Quantum Composer en mi investigación?​

Ejemplo de cita para IBM Quantum Composer:

IBM Quantum Composer. 2025. url: https://quantum.cloud.ibm.com/composer

No veo algo en la interfaz de usuario, como mis tareas de administración.​

Prueba a elegir una cuenta diferente desde el selector de cuentas en el encabezado de la interfaz de IBM Quantum Platform.

Solo uso el Plan Gratuito, pero tuve que ingresar mi tarjeta de crédito. ¿Me cobrarán?​

No se te cobrará a menos que crees una instancia de pago por uso (Pay-As-You-Go) y la uses para enviar cargas de trabajo a las QPUs. Consulta Gestionar costos para obtener instrucciones sobre cómo establecer un límite de costo y conocer otras formas de gestionar los costos.

¿Cuál es la diferencia entre una clave API y un token API?​

No hay diferencia. Los términos clave API y token API se usan indistintamente. Verás ambos términos en la documentación porque distintas interfaces usan distintos términos.

¿Cuál es la diferencia entre un token API y un token bearer?​

Un token API es una credencial de larga duración que se usa para autenticarse en el servicio de Qiskit Runtime. Un token bearer es una credencial temporal que se usa para autenticarse en la API REST en un entorno no confiable. Un token bearer no se puede usar para autenticarse en el servicio de Qiskit Runtime.

¿Tengo que elegir la región en la que vivo?​

No. Puedes usar cualquiera de las dos regiones. La región determina dónde se ejecutan los trabajos y dónde se almacenan los datos. Además, solo puedes ver y usar las instancias que fueron creadas en la región en la que has iniciado sesión. Ten en cuenta que solo la región us-east es compatible con el Plan Gratuito.

¿Puedo conectarme a través de un servidor proxy?​

Sí, pero debes usar Qiskit Runtime v0.44.0 o posterior.

¿Cuál es la política de retención de datos?​

IBM conserva tus datos de trabajos y uso (no eliminados) durante tres años mientras continúes usando el servicio de Qiskit Runtime.

¿Qué pasó con las distribuciones de Python como Qiskit Aer, Qiskit Nature y Qiskit Experiments?​

Desde el lanzamiento de Qiskit SDK v1.0, el comando pip install qiskit instalará únicamente el Qiskit SDK. Esto significa que algunos módulos que usabas en el pasado, como qiskit-aer o qiskit-nature, ahora deben instalarse por separado.

Antes del lanzamiento de Qiskit SDK v1.0, Qiskit estaba compuesto por muchas distribuciones de Python diferentes, como qiskit-terra, el núcleo del compilador; qiskit-aer, el simulador de alto rendimiento; el proveedor original de IBM Quantum®; y varios paquetes ahora obsoletos que ofrecían características algorítmicas exploratorias o de ejecución de experimentos.

Estos paquetes de software separados se combinaron en lo que se llamó el metapaquete de Qiskit, que permitía a los usuarios instalar todos estos componentes juntos mediante pip install qiskit. Esta arquitectura de metapaquete se eliminó con el lanzamiento de Qiskit SDK v1.0, y ahora cada una de las distribuciones de software individuales debe instalarse por separado.

Si quieres instalar los paquetes que antes estaban incluidos en el metapaquete de Qiskit, visita el ecosistema de Qiskit para encontrar una variedad de paquetes que se adapten a tus necesidades. También puedes leer la guía de migración a v1.0 para obtener más información sobre este cambio.
